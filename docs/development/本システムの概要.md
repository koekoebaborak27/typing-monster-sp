# 本システムの概要

クイズモンスター（quiz-monster）がどんなシステムかを、1 ファイルでつかむための資料です。
**このシステムを土台にして、別のゲーム（例: スマホ用のタイピングゲーム）を作るときの出発点**として使えるように書いています。

## このファイルの読み方

各項目に、次の 3 種類の印を付けています。

| 印 | 意味 | 別のゲームにするとき |
| --- | --- | --- |
| 🟦 共通 | ゲームの中身に関係しない土台 | そのまま使う |
| 🟨 調整 | 考え方は同じだが、値や文言が変わる | 値を決め直す |
| 🟥 クイズ固有 | 「3択クイズ」だから存在する部分 | 置き換える |

🟥 と 🟨 の箇所には **「置き換え欄」** を設けています。タイピングゲームにする場合の案を書いてありますが、**案はまだ決定ではありません**。採用するかどうかは、新しいプロジェクトの要件定義で決めてください。

リポジトリを複製する手順そのものは [`本テンプレートPJをコピーする方法.md`](本テンプレートPJをコピーする方法.md) を見てください。

## 1. 一言でいうと

| 項目 | 印 | 本システム（クイズモンスター） | 置き換え欄（タイピングゲームの案） |
| --- | --- | --- | --- |
| 何をするゲームか | 🟥 | 3択クイズに答えてボスモンスターを倒す | 表示された言葉を打ってボスモンスターを倒す |
| 遊ぶ人 | 🟨 | 小学4〜6年生 | （決める） |
| 遊ぶ端末 | 🟦 | スマホ（縦向き固定）。ブラウザで動く Web アプリ（PWA） | 同じ |
| 1回の長さ | 🟨 | 1バトル約1分（5問） | （決める。例: 1バトル約1分） |
| 入力の方法 | 🟥 | 画面の選択肢ボタン（A・B・C）を押す | スマホの文字入力（6章の「スマホならではの検討点」を参照） |
| 学びのねらい | 🟥 | 間違えた問題の解説を読み、同じバトル内と次回以降で解き直す | 打ち間違えた言葉を、同じバトル内と次回以降で打ち直す |
| 記録の保存先 | 🟦 | 端末の localStorage だけ。DB・ログイン・有料 API は使わない | 同じ |

## 2. 技術と運用（🟦 そのまま使える）

| 項目 | 内容 |
| --- | --- |
| 言語・実行環境 | TypeScript / Node.js 24（`.nvmrc`） |
| パッケージ管理 | pnpm（`package.json` の `packageManager` で版を固定） |
| 画面とサーバー | Next.js（App Router）+ React。サーバー側の処理は Route Handlers（出題 API の 1 本だけ） |
| 見た目 | Tailwind CSS。色・大きさなどの値は [`DESIGN.md`](../../DESIGN.md) が正本 |
| 入力の検証 | zod |
| テスト | Vitest（単体）+ Playwright（画面操作） |
| CI | GitHub Actions（lint → format:check → typecheck → test → build）。`*.md` と `docs/` だけの変更では動かない |
| デプロイ | Vercel（Hobby プラン）。`main` への push で自動的に本番へ反映 |
| PWA | Next.js 標準の manifest と、最小限の Service Worker（`public/sw.js`）。オフラインでは遊べず、案内ページ（`public/offline.html`）を出す |
| 音 | Web Audio API でコードから鳴らす（音声ファイルは持たない）。最初のタップで音を有効にする |
| 環境変数 | 無し（`.env` は不要） |

起動は `pnpm install` のあと `pnpm dev`。コマンドの一覧は [`README.md`](../../README.md) にあります。

## 3. ゲームの流れ

### 3.1 骨組み（🟦 共通）

「お題に答える → 合っていればボスに攻撃、間違えればライフが減る → ボスを倒して結果を見る」という骨組みは、クイズでもタイピングでも変わりません。

| 仕組み | 本システムでの内容 | 印 |
| --- | --- | --- |
| ボスの HP | 500。通常のお題 1 つの成功で 100 ダメージ | 🟨 |
| ライフ | 3 つ。通常のお題で失敗すると 1 つ減る | 🟨 |
| ライフ 0 の扱い | ゲームオーバーにせず、ボスが「怒りモード」になって続行する（背景が赤・ボスが震える・名前が「いかりの◯◯」） | 🟦 |
| とどめ | 最後の 2 つのお題。2 つとも成功すれば残り HP に関係なく倒せる（1 つ目で残り HP の半分、2 つ目で残り全部） | 🟦 |
| とどめの失敗 | ライフは減らさず、成功するまで同じお題を出し直す | 🟦 |
| コンボ | 2 連続の成功から「2コンボ！」と表示する（ダメージには影響しない） | 🟦 |
| 評価 | クリア時の残りライフで決める（3=パーフェクト★3 / 2=★2 / 1=★1 / 0=ギリギリ勝利） | 🟦 |
| 必ず勝てる | 負けて終わることが無い。何回失敗しても最後はボスを倒せる | 🟦 |
| 制限時間 | 無し | 🟨 |
| 途中で離れたとき | そのバトルは捨てる（続きからは遊べない）。失敗の記録だけは、その場で保存する | 🟦 |
| ボス | 20 種類（絵文字 + 名前）。毎回ランダムで、直前と同じボスは出さない | 🟨 |
| ボス図鑑 | 倒したボスと撃破回数を見る。撃破回数で枠の色が変わる（1回=銅 / 3回=銀 / 5回=金） | 🟦 |
| 復習モード | 失敗したお題が 5 つ以上たまると遊べる「リベンジモード」。失敗したお題だけで 1 バトルを組む | 🟦 |
| 難易度 | 3 段階（かんたん / ふつう / むずかしい） | 🟨 |

### 3.2 クイズだから存在する部分（🟥 置き換える）

| 項目 | 本システム（クイズ） | 置き換え欄（タイピングゲームの案） |
| --- | --- | --- |
| お題 1 つの形 | 問題文 + 選択肢 3 つ + 正解 + 解説 | 表示する言葉 + 読み（打つ文字の並び） |
| 「成功」の決め方 | 正解の選択肢を押した | 最後まで打ち切った（打ち間違いの許容数は決める） |
| 「失敗」の決め方 | 正解以外の選択肢を押した | （決める。例: 打ち間違いが一定数を超えた／時間切れ） |
| 失敗したときの表示 | 正解の選択肢を光らせ、ひっかけポイントつきの解説を出す。「わかった」を押すまで進まない | （決める。例: 間違えた文字を強調して見せる） |
| とどめの出し直し | 選択肢の並びを入れ替えて同じ問題を出す | 同じ言葉をもう一度打たせる（並べ替えは不要） |
| 難易度の中身 | 学年に対応（1=4年 / 2=5年 / 3=6年 + ひっかけ） | （決める。例: 言葉の長さ・使う文字の種類） |
| 分類 | 教科 5 種（国語・算数・理科・社会・ひらめき）。通常の 3 問は教科が重ならないようにする | （決める。例: 動物・食べ物などの分類。無しでもよい） |
| 制限時間 | 無し | タイピングは速さが楽しさになるので、**時間を入れるかを最初に決める**。入れる場合は 5 章の状態遷移に「時間切れ」が増える |
| 成績の項目 | 残りライフ・撃破回数・パーフェクト回数 | 上記に加えて、打った速さ・正確さを出すかを決める |

## 4. 画面（🟨 骨組みは同じ、バトル画面の中身だけ変わる）

画面は 4 つです。配置の正本は [`docs/specs/mock/screens.html`](../specs/mock/screens.html)、流れの図は [`画面遷移図.md`](../specs/02_basic-design/画面遷移図.md) にあります。

| 画面 | URL | 内容 | 印 |
| --- | --- | --- | --- |
| ホーム | `/` | 難易度を選んでバトルを始める。リベンジモード・ボス図鑑への入口、音の ON/OFF | 🟦 |
| バトル | `/battle` | お題に答えてボスを攻撃する | 🟥 お題と入力の部分 |
| 結果 | `/result` | 評価（★）、図鑑のお知らせ、ふりかえり（失敗したお題）、「もう1回」「ホームへ」 | 🟨 ふりかえりの中身 |
| ボス図鑑 | `/zukan` | 倒したボスと撃破回数、収集率（例: 7 / 20）、図鑑のリセット | 🟦 |

バトル画面は、上から「ボス（HP・名前・吹き出し）→ ライフとコンボ → お題 → 入力する場所」の順に並びます。**置き換えるのは下の 2 つ（お題と入力する場所）だけ**で、ボスまわりの表示と演出はそのまま使えます。

## 5. プログラムの構成

### 5.1 決まり（🟦 共通）

- 依存の向きは `app → modules → shared` の一方向だけです（詳しくは [`src/AGENTS.md`](../../src/AGENTS.md)）。
- `src/app/` は URL と画面をつなぐだけの薄い層で、処理は持ちません。
- 機能ごとに `src/modules/<機能>/` へまとめ、ほかの機能からは `index.ts` に書いたものだけを使います。
- テストは対象ファイルの隣に `<名前>.test.ts` として置きます。

### 5.2 機能ごとの役割と、置き換えの量

| 機能（`src/modules/`） | 役割 | 印 | タイピングゲームにするとき |
| --- | --- | --- | --- |
| `quiz/` | お題のデータ（`data/questions.json`、240問）を持ち、条件に合う 5 問を選んで返す。サーバー専用 | 🟥 | **丸ごと置き換える**（例: `typing/` や `word/`）。データの形・検証・選び方を作り直す |
| `battle/` | バトルの進行（状態の移り変わり・ダメージ・評価）と、ホーム・バトル・結果の 3 画面 | 🟨 | 進行の骨組みは残し、「答える」操作と画面の入力部分を作り直す（下の 5.3） |
| `boss/` | ボス 20 体のデータ、ボスの選び方、図鑑の枠の色、図鑑画面 | 🟦 | ほぼそのまま。ボスの名前だけ見直す（いまは「ウッカリダコ」「ヒッカケオニ」などクイズ向けの名前） |
| `progress/` | 端末（localStorage）への記録の読み書き | 🟨 | 仕組みはそのまま。保存する項目の名前を見直す（下の 5.4） |
| `shared/` | エラーの型、API の入口をくるむ共通処理、Service Worker の登録、小さな共通関数 | 🟦 | そのまま |

### 5.3 `battle/` の中身

| ファイル | 役割 | 印 |
| --- | --- | --- |
| `battle-reducer.ts` | バトル画面の状態を、操作に応じて次の状態へ進める。画面に依存しない純粋な関数 | 🟨 |
| `scoring.ts` | HP・ライフ・評価の計算と、決まった数値（HP 500 など） | 🟨 選択肢の並べ替えだけ 🟥 |
| `battle-result.ts` | 結果画面に出す値を組み立てる | 🟦 |
| `api-client.ts` / `prefetch.ts` | 出題 API を呼ぶ。ホーム画面にいる間に先に取っておく | 🟦 |
| `session.tsx` | バトルの条件と結果を、画面をまたいで持ち運ぶ | 🟦 |
| `sound.ts` | 成功・失敗の音を鳴らす | 🟦 |
| `view.ts` | 状態から、画面に出す文言や見た目の切り替えを決める | 🟨 |
| `ui/home-screen.tsx` / `ui/result-screen.tsx` | ホーム画面・結果画面 | 🟨 文言 |
| `ui/battle-screen.tsx` / `ui/use-battle.ts` | バトル画面と、その状態管理 | 🟥 お題と入力の部分 |

バトル画面の状態は、いま次の 6 つです（[`01_バトル画面の状態遷移.md`](../specs/02_basic-design/battle/01_バトル画面の状態遷移.md)）。

| 状態 | 意味 | タイピングゲームにするとき |
| --- | --- | --- |
| `loading` | お題を取得中 | そのまま |
| `answering` | 解答待ち | **ここが大きく変わる。** クイズは「選択肢を 1 回押す」で終わるが、タイピングは「1 文字ずつ打つ途中経過」を持つ（何文字目まで打ったか・打ち間違いの数など） |
| `correct` | 成功の表示 | そのまま |
| `wrong` | 失敗の表示（解説を出して止まる） | 表示の中身を決め直す |
| `finishing` | とどめの一撃の演出 | そのまま |
| `fetchError` | お題を取得できなかった | そのまま |

### 5.4 データ

**お題のデータ（🟥）** — `src/modules/quiz/data/questions.json`

| 項目 | 本システム（クイズ） | 置き換え欄（タイピングゲームの案） |
| --- | --- | --- |
| `id` | お題の番号。端末の記録に使うので、一度付けたら変えない | 同じ |
| `level` | 難易度 1〜3 | 同じ |
| `genre` | 教科 | 分類（使う場合） |
| `grade` | 学年（使ってよい漢字の範囲を決めるため） | 不要なら削る |
| `question` | 問題文 | 画面に出す言葉（例: 「りんご」） |
| `choices` / `answer` | 選択肢 3 つと正解 | 打つ文字の並び（例: 読み「りんご」。ローマ字で打たせるなら `ringo` も） |
| `explanation` | 解説 | 不要なら削る |

**端末に保存する記録（🟨）** — `src/modules/progress/types.ts` の `Progress`

| 項目 | 内容 | タイピングゲームにするとき |
| --- | --- | --- |
| `version` | 保存データの形の版 | そのまま |
| `wrongIds` | 間違えた問題の ID（次回の優先出題とリベンジモードに使う） | 「打ち間違えた言葉」として使える |
| `recentIds` | 難易度ごとの、最近出た問題の ID（続けて同じ問題を出さないため） | そのまま |
| `lastBossId` | 直前のボス | そのまま |
| `bossKills` | ボスごとの撃破回数 | そのまま |
| `perfectCount` | パーフェクト勝利の回数 | そのまま |
| `soundOn` | 音の ON/OFF | そのまま |
| （無し） | — | 最高速度などを残すなら項目を足す |

> 新しいプロジェクトでは、localStorage の保存名（キー）を必ず別の名前に変えてください。同じ名前のままだと、同じドメインで動かしたときに記録が混ざります。

### 5.5 API（🟨）

サーバー側の処理は **`POST /api/questions`** の 1 本だけです（[`02_APIの入出力.md`](../specs/02_basic-design/question-api/02_APIの入出力.md)）。

- 受け取るもの: モード（通常 / リベンジ）、難易度、最近出た問題の ID、間違えた問題の ID
- 返すもの: 5 問（前の 3 つが通常のお題、後ろの 2 つが予備）と、データに無かった ID

お題をサーバー側に置いているのは、**正解をあらかじめ端末へ渡さないため**です。タイピングゲームには隠す「正解」が無いので、次のどちらにするかを決めてください。

| 案 | 良い点 | 気になる点 |
| --- | --- | --- |
| API を残す | いまの作り（先読み・エラー表示・オフラインの案内）をそのまま使える | サーバーを通す意味は薄い |
| API をやめて、お題を画面側に持つ | 通信が無くなり、オフラインでも遊べるようにできる | 取得まわりの処理と `fetchError` の状態を削る作業が出る |

## 6. タイピングゲームにするときに最初に決めること

次の項目は、土台をコピーしたあと実装に入る前に決めてください。答えによって、作り直す範囲が変わります。

### スマホならではの検討点

| 決めること | 選択肢と注意点 |
| --- | --- |
| 何で入力するか | **(A) スマホ標準のキーボード**: 作る量は少ないが、キーボードが画面の下半分を隠す。予測変換・自動修正・日本語の変換確定が入るため、「1 文字ずつ判定する」作りにしにくい。<br>**(B) 画面内に自前のキーを並べる**: 配置と判定を自由に決められ、ボスの表示も隠れない。キーの数が多いと 1 つが小さくなり押しにくい（[`DESIGN.md`](../../DESIGN.md) の「使いやすさ」の押せる大きさを満たすこと） |
| 何を打たせるか | ひらがな（フリック入力向き）／ローマ字（英字キー向き）／英単語。ローマ字は「し = si / shi」のように打ち方が複数あるので、どれを正しいとするかの決まりが要る |
| 時間を入れるか | 入れるなら「時間切れ」の扱い（ライフを減らすのか、ダメージが減るだけなのか）を決める |
| 1 バトルの量 | いまは 5 つのお題。タイピングは 1 つが短いので、数を増やすかを決める（HP・ダメージの数値も合わせて見直す） |
| 画面の向き | いまは縦向き固定。自前のキーを並べる場合も縦のままでよいかを確かめる |

### 作業の順番（目安）

1. リポジトリを複製する（[`本テンプレートPJをコピーする方法.md`](本テンプレートPJをコピーする方法.md)）。
2. 名前を変える: `package.json` の `name`、`src/app/manifest.ts` のアプリ名、`public/icons/` のアイコン、localStorage の保存名、`README.md`・`AGENTS.md` の冒頭の説明。
3. 上の「最初に決めること」を決め、`docs/specs/01_requirements/` の 🟥 の資料（`battle/`・`question-data/`・`question-api/`）を書き直す。
4. `docs/specs/mock/screens.html` のバトル画面を作り直す（お題と入力する場所）。
5. お題のデータと、それを選ぶ機能（`src/modules/quiz/` に当たるもの）を作る。
6. `battle/` の状態の進め方（`battle-reducer.ts`）に「打っている途中」を足し、バトル画面を作り直す。
7. 結果画面・ホーム画面の文言と、ボスの名前を見直す。
8. `docs/todo/TODO.md` と `docs/todo/history/` は、新しいプロジェクト用に空にしてから書き始める。

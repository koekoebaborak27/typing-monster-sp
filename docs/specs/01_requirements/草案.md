# クイズモンスター 草案

要件定義書を作る前の、現時点の決定事項と未確定事項のまとめ。確定したものは要件定義書（`01_requirements/<機能名>/`）へ移す。

## 1. コンセプト

- 3択クイズに答えてモンスターを倒す、ボスバトル型の学習ゲーム。
- 対象は小学4〜6年生。スマホで使うWebアプリ。
- 1バトル約1分。基本的には誰でも最後はボスを倒せる。上手さは勝ち方の評価で差がつく。
- 間違えた問題は、その場の解説と、バトル最後の「とどめ問題」での出し直しで覚えさせる。

## 2. 技術・運用

- TypeScript + Next.js（App Router）。Vercel（Hobbyプラン・無料）にデプロイ。
- AI API・有料APIは使わない。DBも使わない。
- 学習目的もあるため、サーバー処理（Route Handlers）を含める。そのため静的書き出し（`output: 'export'`）は使わない。
- 問題データは `questions.json` で静的に管理し、AIで事前生成する。品質チェックはオーナーがピックアップで行う（後日）。

## 3. 画面構成（4画面）

| 画面 | 内容 |
| --- | --- |
| ホーム | タイトル、難易度選択（かんたん／ふつう／むずかしい）、リベンジモード（未開放時は鍵マーク）、サウンドON/OFF、ボス図鑑への入口 |
| バトル | ボス（絵文字）、HPバー、ライフ（ハート3つ）、3択の問題、コンボ表示 |
| 結果 | 勝利の種類と★、今回まちがえた問題のふりかえり（正解と解説）、「もう1回」ボタン |
| ボス図鑑 | 20体のボスの一覧と撃破回数（→ 12. ボス図鑑） |

画面イメージ（これをベースにする）：

- バトル画面：[mock/battle.png](../mock/battle.png)

画面イメージからの変更点：

- 上部の表示は「4 / 5問」のみ（Stage は表示しない）。
- HPは草案どおり500。HPバーは比率で表示する。
- ボスは丸い背景の中に絵文字を表示する。怒りモードでは丸を赤くする。
- ボス名は固有名（例：ヒッカケオニ）。怒りモードでは「いかりの◯◯」。
- HPバーの下に、何問目かを示す進み具合のバーを表示する。
- 選択肢には A / B / C のラベルを付ける。とどめ問題の出し直しでは中身だけ並べ替え、ラベルの位置は固定。
- 配色は画面イメージのダーク配色をもとに、`DESIGN.md` へ反映する（TODO「2. 画面イメージ検討」で実施）。
- 画面イメージに無い要素（不正解時の解説と「わかった」ボタン、怒りモードの吹き出しと💢、とどめの一撃の数字）の配置は実装時に決める。

## 4. バトルのルール

### 4.1 基本

- 1バトル5問：通常問題3問＋とどめ問題2問。制限時間・タイマーはなし。
- ボスのHPは500。通常問題の正解1問で100ダメージ。
- ライフは3つ。通常問題で不正解のとき1つ減る。

### 4.2 不正解時

- 自動で次に進まない。
- 正解の選択肢を光らせ、ひっかけポイント付きの一言解説を表示する。
- 「わかった」をタップで次へ進む。

### 4.3 怒りモード（ライフ0）

ライフが0になってもゲームオーバーにはしない。ボスが「怒りモード」になり、そのまま続行する。

- 背景が赤くなる
- ボスが小刻みに震え続ける
- 💢マーク
- 吹き出しで「もうゆるさないぞ！」
- 名前が「いかりの◯◯」に変わる

CSSと文字差し替えのみで実装する。

### 4.4 とどめ問題（2問）

- 通常問題で間違えた問題を出題する。間違いがなければ通常の問題を出題する。
- 2問とも正解すれば、残りHPに関係なくボスを倒せる。
- ダメージ計算：1問目で残りHPの半分、2問目で残りHPすべて（「とどめの一撃」として大きな数字を表示）。
- 間違えた場合：解説を表示したあと、選択肢の並びを入れ替えて同じ問題を出し直す。
  - ライフは減らない。
  - 正解するまで繰り返す。
  - 出し直し分は5問に数えない。

### 4.5 コンボ

- 2問連続正解から「2コンボ！」のように表示するだけ。ダメージへの影響はなし。

### 4.6 サウンド

- Web Audio APIで正解音・不正解音をコード生成する（音声ファイルなし）。
- ブラウザはタップ前に音を鳴らすことを禁止しているため、最初のタップ（バトル開始）で音を有効化する。

### 4.7 途中で離れた場合

- 再読み込み・画面を閉じた場合、そのバトルは破棄する（続きからは遊べない）。
- まちがえた問題の記録は、答えた時点で保存する。
- ホームでON/OFF切り替え可能。

## 5. 結果の評価

クリア時の残りライフで決まる。

| 残りライフ | 評価 |
| --- | --- |
| 3 | パーフェクト勝利（★3） |
| 2 | 勝利（★2） |
| 1 | 勝利（★1） |
| 0 | ギリギリ勝利（★なし） |

通常問題の間違い数ごとの流れ（何問目で間違えたか、とどめ問題の出し直し回数は結果に影響しない）：

| 通常問題の間違い | 通常問題後の残りHP | とどめ1問目 | とどめ2問目 | 残りライフ | 評価 |
| --- | --- | --- | --- | --- | --- |
| 0問 | 200 | 100 | 100 | 3 | パーフェクト（★3） |
| 1問 | 300 | 150 | 150 | 2 | 勝利（★2） |
| 2問 | 400 | 200 | 200 | 1 | 勝利（★1） |
| 3問 | 500 | 250 | 250 | 0（怒りモード） | ギリギリ勝利（★なし） |

結果画面：

- ボタンは「もう1回」「ホームへ」の2つ。
- リベンジモードで、まちがえた問題が5問未満になった場合は「もう1回」を出さず「ぜんぶリベンジした！」と表示する。
- ふりかえり欄（今回まちがえた問題の正解と解説）は、1問も間違えなかった場合「まちがいなし！」と表示する。

- 最高評価は記録しない（すぐ上限に達して変化がなくなるため）。
- 代わりに、遊ぶほど増える記録として「ボスごとの撃破回数」と「パーフェクト勝利の回数」を保存する。

## 6. 難易度

| 難易度 | 内容 |
| --- | --- |
| かんたん | 4年生の内容 |
| ふつう | 5年生の内容 |
| むずかしい | 6年生の内容＋ひっかけ・ひらめき問題 |

- 問題データの `level` 1／2／3 が、かんたん／ふつう／むずかしい にそのまま対応する。`grade` は level と1対1（level 1＝4年、2＝5年、3＝6年）で、使ってよい漢字と内容の範囲を決めるために持つ。
- ジャンル選択はなし。出題は常にミックスで、通常問題3問はすべて異なる教科から出す（とどめ問題は重なってよい）。

## 8. 学びの仕組み

1. 不正解時は答え合わせで止め、正解を表示する。
2. 解説は「正解の理由」だけでなく「なぜ間違えやすいか（ひっかけポイント）」を1行（40字程度）で示す。
3. 同じバトル内で、間違えた問題をとどめ問題として出し直す。
4. 次回以降のバトルでは、選んだ難易度で間違えた問題を1問優先して混ぜ、正解したら優先リストから外す。ほかの難易度で間違えた問題はリベンジモードで出す。

## 9. 問題データ（questions.json）

| 項目 | 内容 |
| --- | --- |
| id | 問題ID |
| genre | 国語／算数／理科／社会／ひらめき |
| grade | 4／5／6 |
| level | 1〜3 |
| question | 問題文 |
| choices | 選択肢（3つ） |
| answer | 正解 |
| explanation | 解説（40字程度） |

- とどめ問題で選択肢を並べ替えるため、答え合わせは選択肢の位置ではなく、選択肢ごとのIDなどで判定できる形にする。
- 問題数：1難易度80問×3＝合計約240問。5教科はなるべく均等に配分。
- 社会は4年生が都道府県・くらしを支える仕事、5年生が国土・産業、6年生が歴史・政治など、学年で範囲が異なる点に注意。
- 漢字はその学年までに習うものだけを使い、ふりがなは付けない。ただし固有名詞（例：富士山、源頼朝）と教科書の用語（例：沸騰、三権分立）は、習っていない漢字でも漢字で書く。国語の読み問題では、答えの漢字が分かってしまわないよう注意する。
- 文字数の目安：問題文60字以内、選択肢15字以内（スマホの1画面に収めるため）。

## 10. サーバー処理（Route Handlers）

| API | 受け取るもの | 返すもの |
| --- | --- | --- |
| 出題API | モード（通常／リベンジ）、難易度（通常のみ）、最近出た問題ID、間違えた問題ID | サーバー側で選んだ5問（正解の選択肢ID・解説を含む）、存在しなかった問題ID |

- 答え合わせは端末内で行う（タップした瞬間に判定し、解答中の通信待ちをなくすため）。そのため答え合わせAPIは作らない。
  - 正解データが端末に渡るが、ランキング等の競う要素がなく、ズルをしても誰も困らないため問題としない。

- 端末から送られた問題IDが `questions.json` に無い場合（問題の削除後など）は、エラーにせず無視して出題する。無かったIDは返事に含め、端末はそれを「まちがえた問題」から消す（リベンジモードの開放条件を正しく数えるため）。
- 400エラーにするのは、送られた内容そのものが壊れている場合だけ（例：難易度が存在しない値、IDの一覧が一覧の形になっていない）。
- リクエストの検証、エラーハンドリング、型定義を学習ポイントとして丁寧に作る。

## 11. 端末内の保存（localStorageのみ）

- まちがえた問題ID（優先出題用）
- 最近出題した問題ID（再出題防止用。難易度ごとに直近20問＝4バトル分）
- ボスごとの撃破回数、パーフェクト勝利の回数
- サウンドON/OFF
- 保存データのバージョン番号（あとで保存の形を変えたとき、古い形のデータを新しい形に作り直して記録を消さないため）

## 12. ボス図鑑

問題図鑑は作らず、ボス図鑑だけにする。

- 1体ごとに表示するのは**絵文字・名前・撃破回数のみ**。見やすさを優先する。
- 未撃破のボスは黒いシルエット（CSS の `filter: brightness(0)`）で、名前は「？？？」。
- 収集率を「7 / 20」の形で表示する。
- 撃破回数で枠の色が変わる：1回＝銅、3回＝銀、5回＝金。
- 結果画面での表示：
  - 初めて倒したとき「NEW！ボス図鑑に登録された！」
  - 枠の色が上がったとき「ランクアップ！」

## 13. リベンジモード（復習モード）

まちがえた問題（優先出題用と同じリスト）からランダムに出題するモード。

- 開放条件：まちがえた問題が5問以上あること。5問未満のときは、ホームのボタンを鍵マーク付きで押せない状態にする。
- 難易度は選ばない。全難易度のまちがえた問題をまとめて使う。
- 構成は通常バトルと同じ（通常問題3問＋とどめ問題2問）で、5問すべてをまちがえた問題から選ぶ。
  - とどめ問題：このバトルの通常問題で間違えた問題を出す。間違いがなければ、残りのまちがえた問題から出す（開放条件が5問以上なので必ず足りる）。
- 正解した問題はまちがえた問題のリストから外す。5問未満になったら未開放に戻す。
- ボスは通常バトルと同じくランダムで、撃破回数・ボス図鑑にも数える。

## 14. 初回リリースに入れないもの

ランキング、デイリー問題、称号、ジャンル選択、タイマー、問題図鑑、記録の消去（誤操作で戻せなくなるため）、アクセス解析

## 15. 動作環境・その他

- 対象：Android の Chrome（最新版）、スマホ縦画面。iPhone は対応しない。
- パソコンで開いた場合は、スマホの幅で中央に表示する。
- 名前などの個人情報の入力欄は作らない。

## 16. PWA

- ホーム画面に追加でき、全画面で開ける。インターネット接続がある前提で、オフラインでは遊べない（「インターネットにつないでね」と表示する）。
- アプリ名・短い名前：クイズモンスター。画面の向きは縦に固定。
- Next.js 標準の manifest と、画面の部品をためておく最小限の Service Worker で作る。追加のライブラリは使わない。
- アイコン画像はオーナーが用意する。PNG で 192×192 と 512×512 の2種類。512×512 は Android が丸や角丸に切り抜くため、絵柄を中央の約8割に収める。

## 17. 速さ

- 解答中は通信しないため、タップした瞬間に正誤を表示する。
- 結果画面を表示している間に、次のバトルの問題を先に取得しておき、「もう1回」ですぐ始められるようにする。
- 出題APIは、起動時にメモリへ読み込んだ問題データから選ぶだけにする（毎回ファイルを読み直さない）。

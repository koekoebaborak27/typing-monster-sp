# 出題API

サーバー処理は Route Handlers で作ること。

## 出題API

| 項目 | 内容 |
| --- | --- |
| 受け取るもの | モード（通常／リベンジ）、難易度（通常のみ）、最近出た問題ID、間違えた問題ID |
| 返すもの | サーバー側で選んだ5問（正解の選択肢ID・解説を含む）、存在しなかった問題ID |

## 答え合わせ

- 答え合わせは端末内で行うこと。タップした瞬間に判定し、解答中の通信待ちをなくすため。
- そのため、答え合わせAPIは作らないこと。
- 正解データが端末に渡ることは問題としない。ランキング等の競う要素がなく、ズルをしても誰も困らないため。

## 存在しない問題IDの扱い

- 端末から送られた問題IDが `questions.json` に無い場合（問題の削除後など）は、エラーにせず無視して出題すること。
- 無かったIDは返事に含めること。端末はそれを「まちがえた問題」から消す（リベンジモードの開放条件を正しく数えるため）。

## エラー

- 400エラーにするのは、送られた内容そのものが壊れている場合だけとすること（例：難易度が存在しない値、IDの一覧が一覧の形になっていない）。

## 実装方針

- 出題APIは、起動時にメモリへ読み込んだ問題データから選ぶだけにすること。
- リクエストの検証、エラーハンドリング、型定義を学習ポイントとして丁寧に作ること。

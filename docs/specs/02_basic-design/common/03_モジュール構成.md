# モジュール構成

依存方向は `app → modules → shared` の一方向（[src/AGENTS.md](../../../../src/AGENTS.md)）。モジュール同士は互いの `index.ts` だけを使う。

ここに書くのは、タイピングゲームへ作り替えたあとの姿。作り替えがどこまで進んだかは [`docs/todo/TODO.md`](../../../todo/TODO.md) を見る。

## モジュール

すべて端末（クライアント）で動く。サーバー側の処理は持たない。

| モジュール | 役割 |
| --- | --- |
| `word` | 言葉のデータ、1バトルの5語の選び方 |
| `battle` | ホーム・バトル・結果の画面、バトルの進行（状態遷移・1文字ごとの判定・ダメージ・評価）、サウンド、`BattleSession` |
| `progress` | localStorage の読み書き（最近出た言葉・直前のボス・撃破回数・パーフェクト回数・サウンド設定） |
| `boss` | ボス一覧、ボスの選び方、枠ランクの判定、ボス図鑑の画面 |

## 依存関係

```
app/ ──→ battle    （ホーム・バトル・結果ページ、layout の BattleSession）
app/ ──→ boss      （図鑑ページ）
battle ──→ word, progress, boss
boss ──→ progress
word  : 他のモジュールに依存しない
```

- `battle` が `word` に依存するのは、バトルの開始時に5語を選ぶため。
- `boss` が `progress` に依存するのは、撃破回数を図鑑に出すため。
- `word` は `progress` を使わない。最近出た言葉のIDは、`battle` が `progress` から読んで `word` へ渡す。

## 公開API（index.ts）

| モジュール | 公開するもの |
| --- | --- |
| `word` | `pickWords(recentIds, random)` と型（`Word`） |
| `progress` | `loadProgress()`、`recordBattleStart(bossId, wordIds)`、`recordBattleWin(bossId, isPerfect)`、`resetZukan()`、`setSoundOn(on)`、`isStorageAvailable()` と型 |
| `boss` | `BOSSES`、`pickBoss(lastBossId, random)`、`getRank(killCount)`、`getZukanNotice(killCountBefore)`、`BossZukanScreen` と型 |
| `battle` | `BattleSessionProvider`、`HomeScreen`、`BattleScreen`、`ResultScreen` |

関数の引数・戻り値の細部は実装時に型で決める（基本設計では名前と役割だけを決める）。

## ファイル構成

```
src/
├─ app/
│  ├─ layout.tsx               ← BattleSessionProvider、manifest、Service Worker 登録
│  ├─ page.tsx                 ← HomeScreen を置くだけ
│  ├─ battle/page.tsx
│  ├─ result/page.tsx
│  ├─ zukan/page.tsx
│  └─ manifest.ts              ← Next.js 標準の manifest
├─ modules/
│  ├─ word/        （言葉のデータ）  pick-words.ts  types.ts  index.ts
│  ├─ battle/      ui/*.tsx  ui/use-battle.ts  battle-reducer.ts  judge.ts  scoring.ts  battle-result.ts  view.ts  sound.ts  session.tsx  types.ts  index.ts
│  ├─ progress/    storage.ts  schema.ts  service.ts  types.ts  index.ts
│  └─ boss/        data/bosses.ts  pick-boss.ts  rank.ts  zukan.ts  ui/*.tsx  types.ts  index.ts
└─ shared/
   └─ ui/          utils.ts（cn）、Service Worker の登録など共通部品
```

| ファイル | 役割 |
| --- | --- |
| `word/pick-words.ts` | 最近出た言葉を避けて5語を選ぶ（[お題の選び方](../battle/05_お題の選び方.md)） |
| `battle/battle-reducer.ts` | バトルの状態を変える（[状態の遷移](../battle/01_バトル画面の状態遷移.md#状態の遷移)） |
| `battle/judge.ts` | 入力欄の中身をお題と比べる（[ミスの数え方](../battle/01_バトル画面の状態遷移.md#ミスの数え方)） |
| `battle/scoring.ts` | ダメージの計算、ミスの回数から評価を決める |
| `battle/battle-result.ts` | 結果画面へ渡す値を作る（[結果の作り方](../battle/02_結果画面の表示.md#結果の作り方)） |
| `battle/view.ts` | 状態から、画面に出す文言や幅を作る（「2 / 5問」、進み具合バーの幅、知らせる文など） |
| `battle/ui/use-battle.ts` | バトル画面用のフック。保存・音・時間待ち・入力欄の操作を受け持つ（[バトル進行の処理の分け方](../../03_detail-design/battle/01_バトル進行の処理の分け方.md)） |

- 言葉のデータを置くファイルの名前と形は、まだ決めていない（言葉を作るときに決める）。置くのは `word` モジュールの中とする。
- `pick-words.ts`・`battle-reducer.ts`・`judge.ts`・`scoring.ts`・`battle-result.ts`・`view.ts`・`pick-boss.ts`・`rank.ts` は、同じ入力なら必ず同じ結果を返し、画面や localStorage に触れない関数にする（単体テストで結果を固定できるようにするため）。乱数は引数で受け取る。
- 画面コンポーネントは、`battle-reducer.ts` が返す状態を描画し、操作をフックへ渡すだけにする。
- DB は無いため、`shared/db` と `prisma/` は作らない。

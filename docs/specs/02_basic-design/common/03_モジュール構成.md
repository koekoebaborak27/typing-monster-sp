# モジュール構成

依存方向は `app → modules → shared` の一方向（[src/AGENTS.md](../../../../src/AGENTS.md)）。モジュール同士は互いの `index.ts` だけを使う。

## モジュール

| モジュール | 役割 | 実行場所 |
| --- | --- | --- |
| `quiz` | 問題データの読み込み、出題の選び方、出題APIのリクエスト検証 | サーバーのみ |
| `battle` | ホーム・バトル・結果の画面、バトルの進行（状態遷移・ダメージ・評価）、出題APIの呼び出し、サウンド、`BattleSession` | クライアント |
| `progress` | localStorage の読み書き（まちがえた問題・最近出た問題・撃破回数・パーフェクト回数・サウンド設定） | クライアント |
| `boss` | ボス一覧、ボスの選び方、枠ランクの判定、ボス図鑑の画面 | クライアント |

## 依存関係

```
app/ ──→ quiz      （Route Handler が出題を呼ぶ）
app/ ──→ battle    （ホーム・バトル・結果ページ、layout の BattleSession）
app/ ──→ boss      （図鑑ページ）
battle ──→ progress, boss
boss ──→ progress
quiz  : 他のモジュールに依存しない
```

- `battle` は `quiz` を実行時には呼ばない（HTTP で出題APIを呼ぶ）。型だけ `import type` で使う。
- `boss` が `progress` に依存するのは、撃破回数を図鑑に出すため。

## 公開API（index.ts）

| モジュール | 公開するもの |
| --- | --- |
| `quiz` | `selectQuestions(request)`、`parseQuestionRequest(body)`、型（`Question`・`QuestionRequest`・`QuestionResponse`）。`server-only`。クライアントからは型を `import type` で使うだけにする |
| `progress` | `loadProgress()`、`recordFirstAnswer(questionId, isCorrect)`、`recordRecentIds(level, ids)`、`recordLastBoss(bossId)`、`recordBattleWin(bossId, isPerfect)`、`removeWrongIds(ids)`、`setSoundOn(on)`、`isStorageAvailable()` と型 |
| `boss` | `BOSSES`、`pickBoss(lastBossId, random)`、`getRank(killCount)`、`getZukanNotice(killCountBefore)`、`BossZukanScreen` と型 |
| `battle` | `BattleSessionProvider`、`HomeScreen`、`BattleScreen`、`ResultScreen` |

関数の引数・戻り値の細部は実装時に型で決める（基本設計では名前と役割だけを決める）。

## ファイル構成

```
src/
├─ app/
│  ├─ layout.tsx               ← BattleSessionProvider、manifest、Service Worker 登録
│  ├─ page.tsx                 ← HomeScreen を置くだけ
│  ├─ battle/page.tsx
│  ├─ result/page.tsx
│  ├─ zukan/page.tsx
│  ├─ manifest.ts              ← Next.js 標準の manifest
│  └─ api/questions/route.ts   ← 出題API。parse → selectQuestions → 応答だけ
├─ modules/
│  ├─ quiz/        data/questions.json  repository.ts  selection.ts  validation.ts  types.ts  index.ts
│  ├─ battle/      ui/*.tsx  battle-reducer.ts  scoring.ts  api-client.ts  sound.ts  session.tsx  index.ts
│  ├─ progress/    storage.ts  schema.ts  service.ts  types.ts  index.ts
│  └─ boss/        data/bosses.ts  pick-boss.ts  rank.ts  ui/*.tsx  index.ts
└─ shared/
   ├─ errors/      app-error.ts    ← AppError / Errors（出題APIの 400・409 に使う）
   ├─ observability/               ← API 用のラッパー（ログは境界で1回だけ）
   └─ ui/          utils.ts（cn）など共通部品
```

- 出題の選び方（`selection.ts`）は、乱数と問題一覧を引数で受け取る純粋関数にする（単体テストで結果を固定できるようにするため）。`battle-reducer.ts`・`scoring.ts`・`pick-boss.ts`・`rank.ts` も同様に、画面や localStorage に触れない純粋関数にする。
- 問題データを読むのは `repository.ts` だけ。モジュールの起動時に1回だけ読み込んでメモリに持つ（[出題API](../../01_requirements/question-api/01_出題API.md)）。
- 画面コンポーネントは、`battle-reducer.ts` が返す状態を描画し、操作を `dispatch` するだけにする。
- DB は無いため、`shared/db` と `prisma/` は作らない。

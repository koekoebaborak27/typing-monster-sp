# BattleSessionと先読み

`BattleSession` の役割は [画面間で受け渡すもの](../../02_basic-design/common/01_URLと画面遷移.md#画面間で受け渡すもの)、先読みの手順は [先読み](../../02_basic-design/question-api/01_出題の選び方.md#先読み) で決めている。ここでは、持つ値の型と、先読みの途中で別の操作をされたときの扱いを決める。

## 持つ値

`session.tsx` の `BattleSessionProvider` が持つ。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `start` | `BattleStart` \| `null` | 次に始めるバトルの条件。`{ mode: "normal", level }` または `{ mode: "revenge" }` |
| `result` | `BattleResult` \| `null` | 結果画面に出す値。中身は [結果の作り方](../../02_basic-design/battle/02_結果画面の表示.md#結果の作り方) の表 |
| 先読み | 下記 | 次のバトルの問題の取得 |

- `start` と `result` は画面の表示に使うので、React の状態（`useState`）で持つ。
- 先読みは画面に表示しない（待つのはバトル画面の「よみこみ中…」で足りる）ため、`useRef` で持つ。中身は次の4つ。

| 項目 | 内容 |
| --- | --- |
| `id` | 先読みのたびに1つ増やす番号。古い取得の返事かどうかを見分ける |
| `start` | 何の条件で取得したか |
| `promise` | 出題APIの返事を待つ Promise。成功・失敗の結果もここから受け取る |
| `failed` | 失敗が分かったら `true` にする |

## 値を変える場面

| 場面 | `start` | `result` | 先読み |
| --- | --- | --- | --- |
| ホームで難易度／リベンジを押す | 押した条件 | `null` | 捨てる |
| バトル画面で取得を始める | | `null` | 使えるものがあれば取り出し、空にする（下記） |
| とどめの一撃 | | 結果を置く | |
| 結果画面を開く | | | 条件を満たせば始める（下記） |
| 結果で「もう1回」 | そのまま | | そのまま（バトル画面が取り出す） |
| 結果で「ホームへ」 | | | 捨てる |

- 「捨てる」は、先読みの `ref` を空にするだけでよい。取得中の返事が後から届いても、`ref` の `id` と合わないので使われない。
- 結果画面の `result` はバトル開始時に `null` に戻す。URL を直接入力して `/result` を開いたときに、前のバトルの結果を出さないため（[直接開いたとき](../../02_basic-design/common/01_URLと画面遷移.md#直接開いたとき再読み込み)）。

## 先読みを始める（結果画面）

- `result.revengeCleared` が `true` のときは始めない。
- 出題APIへ送る `wrongIds`・`recentIds` は、`api-client.ts` が**呼ぶ時点で**保存データから読む。撃破の記録はバトル画面で保存済みなので、最新の内容が送られる。
- 同じ結果に対してすでに先読みがあれば、新しく始めない。開発時の React は画面を開いたときの処理を2回動かすことがあり、出題APIを2回呼ばないようにするため。

## 先読みを取り出す（バトル画面）

バトル画面は、問題を取得するときに `takePrefetch(start)` を呼ぶ。

| 先読みの状態 | 返すもの | バトル画面の動作 |
| --- | --- | --- |
| 無い、または条件（`start`）が違う | `null` | 出題APIを新しく呼ぶ |
| 失敗している（`failed`） | `null` | 出題APIを新しく呼ぶ（[エラーと特殊表示](../../02_basic-design/common/02_エラーと特殊表示.md#一覧) の「先読みが失敗しても結果画面には出さない」のとおり、ここで取得し直す） |
| 取得中・取得済み | `promise` | その返事を待つ。取得中なら、その間「よみこみ中…」を出す |

- 取り出したら先読みを空にする。同じ問題で2回バトルしないため。
- 取り出した返事が失敗だった場合（取得中に失敗したとき）は、新しく呼んだときの失敗と同じに扱う（取得エラーを出す）。409 の扱いも同じ。
- 先読みした問題の `recentIds` への追加は、通常の取得と同じく、取得が成功してバトルを始めるときに行う（[バトル進行の処理の分け方](01_バトル進行の処理の分け方.md#フックの流れ) の手順2）。「ホームへ」で捨てた問題は追加されない。

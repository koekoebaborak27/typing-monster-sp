# バトル進行の処理の分け方

状態・遷移・表示の条件は [バトル画面の状態遷移](../../02_basic-design/battle/01_バトル画面の状態遷移.md) で決めている。ここでは、それを**どの関数・どの場所で実装するか**を決める。

## 方針

`battle-reducer.ts` は、同じ入力なら必ず同じ結果を返し、画面・localStorage・タイマー・音に触れない関数にする（[モジュール構成](../../02_basic-design/common/03_モジュール構成.md#ファイル構成)）。そのために、バトルの処理を次の 3 つに分ける。

| 分類 | 置き場所 | 例 |
| --- | --- | --- |
| 状態を変える | `battle-reducer.ts` の `battleReducer(state, action)` | 何文字目まで打ったか・ミスの回数・HP の更新 |
| 状態の変化に伴う処理を**列挙する** | `battle-reducer.ts` の `listEffects(prev, next)` | 「ミスの音を鳴らす」「撃破を記録する」「入力欄を空にする」を一覧にして返すだけ。実行はしない |
| 列挙された処理を**実行する**・時間を待つ | `ui/use-battle.ts`（バトル画面用のフック） | localStorage への保存、音を鳴らす、1秒・2秒待つ、入力欄を空にする |

- 「何をするか」の判断を `listEffects` に集めることで、「ミスの音は数えたときだけ」「勝利の記録は1回だけ」などの規則を単体テストで確かめられる。
- 乱数は reducer の中で作らない。ボスと5語は、フックが `Math.random` を使って選び、初期状態に入れて渡す。
- 入力欄の中身とお題を比べる処理は `judge.ts` の `judgeInput(target, value)` に分ける（[1文字ごとの判定](02_1文字ごとの判定.md)）。reducer は、その結果を使って状態を変えるだけにする。

## 状態の型

基本設計の [バトルが持つ状態](../../02_basic-design/battle/01_バトル画面の状態遷移.md#バトルが持つ状態) を、次の型で持つ。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `phase` | `"typing"` \| `"damage"` \| `"finishing"` | 入力待ち・ダメージ表示・とどめの一撃 |
| `boss` | `Boss` | 今回のボス |
| `words` | `Word[]`（5語） | お題 |
| `slot` | `number` | 何問目か（0〜4） |
| `hp` | `number` | ボスの残りHP |
| `typedCount` | `number` | 何文字目まで正しく打てたか |
| `wrongText` | `string` | 入力欄に残っている、お題と違う部分 |
| `needsJapaneseInput` | `boolean` | 日本語入力がオフのまま打っていると見なしたか |
| `missCount` | `number` | ミスの回数 |
| `lastDamage` | `number` | 直前に与えたダメージ |

- 初期状態は `createInitialState(boss, words)` で作る。
- 今のお題は `words[slot]`。これを返す関数 `currentWord(state)` を用意し、画面と reducer の両方で使う。
- 怒りモードかどうか（`missCount` が 5 以上）、進み具合バーの幅など、状態から計算できるものは状態に持たせない（`view.ts` で作る）。
- 入力欄の中身そのものと、打っている途中の形は、状態に持たない。入力欄は端末のキーボードが書き換えるので、中身は入力欄が持つ。画面に色を付けるのに要るのは `typedCount` と `wrongText` だけで足りる。

## 操作（action）の一覧

| 操作 | 渡す値 | 起こすもの |
| --- | --- | --- |
| `inputChanged` | `value`（入力欄の中身の全体） | 入力欄の中身が変わった。`phase` が `typing` 以外のときは何もしない |
| `damageShown` | | ダメージ表示から約1秒たった。`phase` が `damage` 以外のときは何もしない |

- とどめの一撃から結果画面へ移る操作は作らない。`phase` が `finishing` になったら、フックが2秒待って `/result` へ移る（バトル画面はそこで終わるため、状態を変える必要が無い）。

`inputChanged` での状態の変え方は次のとおり（`result` は `judgeInput(今のお題, value)` の結果）。

| `result` | 変えるもの |
| --- | --- |
| `missed` が `false` で、`confirmed` がお題の文字数に届いていない | `typedCount` = `confirmed`、`wrongText` = 空、`needsJapaneseInput` = `false` |
| `missed` が `false` で、`confirmed` がお題の文字数と同じ | HP を減らし、`lastDamage` を入れ、`typedCount` = `confirmed`。`slot` が 4 なら `finishing`、それ以外は `damage` へ |
| `missed` が `true` | `typedCount` = `confirmed`、`wrongText` = `value` の `confirmed` 文字目より後ろ、`needsJapaneseInput` = `result.tooManyLetters`。**変える前の `wrongText` が空のときだけ** `missCount` +1 |

- 「直前は合っていたか」は、変える前の `wrongText` が空かどうかで見分ける（[ミスの数え方](../../02_basic-design/battle/01_バトル画面の状態遷移.md#ミスの数え方)）。そのための項目を別に持たない。
- HP の減らし方は `scoring.ts` の関数を使う（1〜3問目は `hpAfterNormalHit`、4問目は `hpAfterFinishFirstHit`、5問目は 0）。

## 状態の変化に伴う処理（`listEffects`）

`listEffects(prev, next)` は、変化の前後の状態を比べて、実行すべき処理を次の形の配列で返す。

| 条件（前 → 後） | 返す処理 |
| --- | --- |
| `missCount` が増えた | `{ type: "playSound", kind: "miss" }` |
| `typing` → `damage` / `finishing` | `{ type: "playSound", kind: "complete" }` |
| `damage` → `typing` | `{ type: "clearInput" }` |
| → `finishing` | `{ type: "recordBattleWin", bossId, isPerfect }`（`isPerfect` は `missCount` が 0） |

- 音を鳴らすかどうか（サウンドON/OFF）は、実行するフックの側で判断する。`listEffects` は鳴らす場面を返すだけ。
- バトル開始時の保存（`recordBattleStart`）は、状態の変化ではないので `listEffects` では返さない。フックが、初期状態を作る前に行う。

## フックの流れ

画面コンポーネントは、このフックが返す状態を描画し、入力欄の通知をフックへ渡すだけにする。

1. **画面を開いたとき**：`BattleSession` の `canStart` が `false` なら `/` へ置き換える。`true` なら、保存データを読み、`pickBoss(lastBossId)` でボスを、`pickWords(recentIds)` で5語を選ぶ → `recordBattleStart(bossId, wordIds)` で保存する → `BattleSession` の `result` を `null` に戻す → `createInitialState(boss, words)` を状態にする。
   - 選ぶ・保存するのは、1回のバトルにつき1回だけにする。開発時の React は画面を開いたときの処理を2回動かすことがあるので、済んだかどうかの印を持つ。
2. **入力欄を選ぶ**：状態ができたら入力欄を選んだ状態にする（`focus()`）。キーボードが出なかった機種では、入力欄をタップすれば出る。
3. **入力欄の中身が変わったとき**（`input` の通知）：入力欄の中身の全体を読み、`inputChanged` を送る。変換中かどうかは問わない（変換中の通知も、中身が変わるたびに同じように送る）。
4. **操作を送るとき**：`next = battleReducer(state, action)` を先に計算し、`listEffects(state, next)` の処理を実行してから `dispatch(action)` する。
   - 保存や音は、画面の再描画をきっかけに動く `useEffect` ではなく、操作を受け取った処理の中で行う。開発時の React は `useEffect` を2回動かすことがあり、記録が二重になるのを防ぐため。
   - `recordBattleWin` を実行するときは、更新前後の撃破回数を使って結果を作り（`battle-result.ts` の `buildBattleResult`）、`BattleSession` に置く（[結果の作り方](../../02_basic-design/battle/02_結果画面の表示.md#結果の作り方)）。
   - `clearInput` を実行するときは、入力欄の中身を空にする。**入力欄をこちらで書き換えるのは、この時だけ**（変換中の文字を何度も書き換えると、キーボードの側の覚えている文字とずれるため）。
5. **時間待ち**：`phase` が `damage` になったら約1秒後に `damageShown` を送る。`finishing` になったら入力欄を打てない状態にし、約2秒後に `/result` へ置き換える。待ちは `useEffect` の中の `setTimeout` で行い、画面を離れたら止める。
6. **画面を離れたとき**（端末の戻る操作など）：待ちを止める。そのバトルは破棄する。

## 単体テストの対象

| 関数 | 確かめること |
| --- | --- |
| `battleReducer` | [状態の遷移](../../02_basic-design/battle/01_バトル画面の状態遷移.md#状態の遷移) の表の各行。違う文字が残っている間は `missCount` が増えないこと、消して合っている状態に戻ったあとは次の1回を数えること。`typing` 以外での `inputChanged` を無視すること。HP が 500 → 400 → 300 → 200 → 100 → 0 と減ること |
| `listEffects` | ミスの音は `missCount` が増えたときだけ返すこと。`recordBattleWin` は `finishing` になったときに1回だけ返し、`isPerfect` がミス0回のときだけ `true` になること。`clearInput` は次のお題へ進むときだけ返すこと |
| `judgeInput` | [1文字ごとの判定](02_1文字ごとの判定.md#単体テストで確かめること) |
| `scoring.ts` の評価 | ミス 0・1・2・3・4・5 回の評価（境目の値） |

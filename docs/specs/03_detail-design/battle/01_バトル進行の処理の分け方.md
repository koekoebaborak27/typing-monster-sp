# バトル進行の処理の分け方

状態・遷移・表示の条件は [バトル画面の状態遷移](../../02_basic-design/battle/01_バトル画面の状態遷移.md) で決めている。ここでは、それを**どの関数・どの場所で実装するか**を決める。

## 方針

`battle-reducer.ts` は、同じ入力なら必ず同じ結果を返し、画面・localStorage・タイマー・音に触れない関数にする（[モジュール構成](../../02_basic-design/common/03_モジュール構成.md#ファイル構成)）。そのために、バトルの処理を次の 3 つに分ける。

| 分類 | 置き場所 | 例 |
| --- | --- | --- |
| 状態を変える | `battle-reducer.ts` の `battleReducer(state, action)` | HP・ライフ・コンボの更新、とどめ問題の決定 |
| 状態の変化に伴う処理を**列挙する** | `battle-reducer.ts` の `listEffects(prev, next)` | 「この問題の最初の解答を記録する」「正解音を鳴らす」を一覧にして返すだけ。実行はしない |
| 列挙された処理を**実行する**・時間を待つ | `ui/use-battle.ts`（バトル画面用のフック。基本設計のファイル構成に追加する） | localStorage への保存、音を鳴らす、1秒・2秒待つ、出題APIを呼ぶ |

- 「何をするか」の判断を `listEffects` に集めることで、「出し直しの解答では記録しない」「勝利の記録は1回だけ」などの規則を単体テストで確かめられる。
- 乱数は reducer の中で作らない。ボスの選択と、出し直しの選択肢の並べ替えは、呼ぶ側が `Math.random` を使って決め、結果を操作（action）に入れて渡す。

## 状態の型

基本設計の [バトルが持つ状態](../../02_basic-design/battle/01_バトル画面の状態遷移.md#バトルが持つ状態) に、実装に必要な次の値を足す。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `phase` | `"loading"` \| `"answering"` \| `"correct"` \| `"wrong"` \| `"finishing"` \| `"fetchError"` | 読み込み中・解答待ち・正解表示・不正解表示・とどめの一撃・取得エラー |
| `fetchError` | `"offline"` \| `"failed"` \| `"revengeUnavailable"` \| `null` | 取得エラーの種類。表示する文言とボタンを切り替える（[エラーと特殊表示](../../02_basic-design/common/02_エラーと特殊表示.md#一覧)） |
| `questions` | `Question[]` | 出題APIが返した5問（通常3問＋予備2問）。読み込み中は空 |
| `finishQuestions` | `[Question, Question]` \| `null` | とどめ問題2問。`slot` が 2 から 3 へ進むときに決める |
| `boss` | `Boss` \| `null` | 今回のボス |
| `selectedChoiceId` | `string` \| `null` | 直前に選んだ選択肢。正解表示・不正解表示で色を付けるために使う |
| `finishDamage` | `number` | とどめの一撃で出す大きな数字（2問目に正解する直前の `hp`） |

- 今の問題は、`slot` が 0〜2 なら `questions[slot]`、3〜4 なら `finishQuestions[slot - 3]` とする。これを返す関数 `currentQuestion(state)` を用意し、画面と reducer の両方で使う。
- 怒りモードかどうか（`life` が 0）など、状態から計算できるものは状態に持たせない。

## 操作（action）の一覧

| 操作 | 渡す値 | 起こすもの |
| --- | --- | --- |
| `fetchStarted` | | 「もういちど」を押した。`phase` を読み込み中に戻す |
| `fetchSucceeded` | `questions`、`boss` | 出題APIが成功した。`boss` は呼ぶ側が `pickBoss` で選んで渡す |
| `fetchFailed` | `fetchError` | 出題APIが失敗した |
| `answered` | `choiceId` | 選択肢を押した。`phase` が `answering` 以外のときは何もしない |
| `correctShown` | | 正解表示から約1秒たった |
| `acknowledged` | `retryOrder` | 「わかった」を押した。`retryOrder` は出し直し用に並べ替えた選択肢の順で、呼ぶ側が毎回作って渡す。通常問題では使わない |

- とどめの一撃から結果画面へ移る操作は作らない。`phase` が `finishing` になったら、フックが2秒待って `/result` へ移る（バトル画面はそこで終わるため、状態を変える必要が無い）。
- `retryOrder` は `scoring.ts` の `reorderForRetry(order, answerId, random)` で作る。正解の位置が前回と変わるまで並べ替え直す（[状態の遷移](../../02_basic-design/battle/01_バトル画面の状態遷移.md#状態の遷移) の注記）。`random` を引数で受け取るので、単体テストで結果を固定できる。

## とどめ問題の決定

`correctShown` または `acknowledged` で `slot` が 2 から 3 へ進むときに、reducer が `normalWrong` と予備2問（`questions[3]`・`questions[4]`）から決め、`finishQuestions` に入れる。決め方は [返す5問の意味](../../02_basic-design/question-api/01_出題の選び方.md#返す5問の意味) の表のとおり。表の処理は `decideFinishQuestions(normalWrong, spares)` として切り出し、単体テストで4通り（間違い0〜3問）を確かめる。

## 状態の変化に伴う処理（`listEffects`）

`listEffects(prev, next)` は、変化の前後の状態を比べて、実行すべき処理を次の形の配列で返す。

| 条件（前 → 後） | 返す処理 |
| --- | --- |
| `answering` → `correct` / `finishing` | `{ type: "playSound", kind: "correct" }` |
| `answering` → `wrong` | `{ type: "playSound", kind: "wrong" }` |
| `answering` から抜けた、かつ `prev.isRetry` が `false` | `{ type: "recordFirstAnswer", questionId, isCorrect }` |
| → `finishing` | `{ type: "recordBattleWin", bossId, isPerfect }`（`isPerfect` は `life` が 3） |

- 音を鳴らすかどうか（サウンドON/OFF）は、実行するフックの側で判断する。`listEffects` は鳴らす場面を返すだけ。
- 通常問題で間違えた問題が、とどめ問題として再び出たとき（`isRetry` は `false`）は、最初の解答はすでに記録済みなので `recordFirstAnswer` を返さない。`reviewList` にも同じ問題を二重に入れない。
- バトル開始時の保存（`lastBossId`・`recentIds`・`unknownIds` の削除）は、`fetchSucceeded` を送る**前**にフックが行う。ボスを選ぶのに最新の `lastBossId` が要り、選んだらすぐ保存する必要があるため（[ボスの選び方](../../02_basic-design/boss-zukan/01_ボスデータと選び方.md#ボスの選び方)）。

## フックの流れ

画面コンポーネントは、このフックが返す状態を描画し、押された操作をフックへ渡すだけにする。

1. **画面を開いたとき**：`BattleSession` に開始情報が無ければ `/` へ置き換える。あれば問題を取得する（先読み済みの問題があればそれを使う。[BattleSessionと先読み](02_BattleSessionと先読み.md)）。
2. **取得が成功したとき**：`unknownIds` を「まちがえた問題」から外す → 保存データを読み、`pickBoss(lastBossId)` でボスを選ぶ → `lastBossId` を保存する → 通常モードなら `recentIds` を保存する → `fetchSucceeded` を送る。
3. **取得が失敗したとき**：409 なら `unknownIds` を「まちがえた問題」から外してから、`fetchFailed("revengeUnavailable")` を送る。それ以外は `navigator.onLine` で `offline` か `failed` を決めて送る。
4. **操作を受け取ったとき**：`next = battleReducer(state, action)` を先に計算し、`listEffects(state, next)` の処理を実行してから `dispatch(action)` する。
   - 保存や音は、画面の再描画をきっかけに動く `useEffect` ではなく、操作を受け取った処理の中で行う。開発時の React は `useEffect` を2回動かすことがあり、記録が二重になるのを防ぐため。
   - `recordBattleWin` を実行するときは、更新前後の撃破回数を使って結果を作り、`BattleSession` に置く（[結果の作り方](../../02_basic-design/battle/02_結果画面の表示.md#結果の作り方)）。
5. **時間待ち**：`phase` が `correct` になったら約1秒後に `correctShown` を送る。`finishing` になったら約2秒後に `/result` へ置き換える。待ちは `useEffect` の中の `setTimeout` で行い、画面を離れたら止める。
6. **画面を離れたとき**（端末の戻る操作など）：待ちを止め、取得中の出題APIの返事は使わない（`AbortController` で取り消す）。

## 単体テストの対象

| 関数 | 確かめること |
| --- | --- |
| `battleReducer` | [状態の遷移](../../02_basic-design/battle/01_バトル画面の状態遷移.md#状態の遷移) の表の各行。`answering` 以外での `answered` を無視すること |
| `decideFinishQuestions` | 通常問題の間違いが0〜3問のときの、とどめ問題の組み合わせ |
| `listEffects` | 出し直しの解答では `recordFirstAnswer` を返さないこと。`recordBattleWin` は `finishing` になったときに1回だけ返すこと |
| `reorderForRetry` | 正解の位置が前回と必ず変わること |

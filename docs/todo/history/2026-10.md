## 2026-10-13 タイピングゲームへの作り替えの方針決め

クイズモンスターのソースをコピーしたフォルダを、スマホ用のタイピングゲームへ作り替えることにし、実装の前に仕様と手順を決めた（プログラムはまだ変えていない）。クイズモンスターのときの記録（2026-10-09 まで）は、このリポジトリからは消した。

**決めた仕様**（設計書へ書き写すまでは、ここが正本）

| 項目 | 内容 |
| --- | --- |
| 遊ぶ人・端末 | 小学校高学年。スマホ（縦向き） |
| 入力 | スマホ標準のキーボード（フリック入力）。ひらがなだけ |
| お題 | ひらがなの言葉をそのまま表示する。約 100 語、分類なし、難易度なし |
| 1 バトル | 5 問。通常 3 問（1 問 100 ダメージ）+ とどめ 2 問（残り HP の半分 → 残り全部） |
| ミスの判定 | 1 文字ごと。お題の次の文字と違う文字が入ったらミス 1 回とし、その文字を取り消す。打ち直せば先へ進める |
| 途中の形 | 「が」を打つ途中の「か」、「っ」の途中の「つ」、「ぱ」の途中の「は」「ば」はミスにしない。同じキーを連打する打ち方（か→き→く）はミスに数える |
| 失敗・ライフ | 無くす。問題を間違えるという考えが無いので、とどめの出し直しと予備の問題も無くす |
| いかり | ミスが 5 回以上で、ボスが「いかりの◯◯」になる |
| 評価 | ミスの回数で決める |
| 時間 | 制限時間も、速さの記録も入れない |
| お題の置き場所 | 画面側に持つ。出題 API はやめる |
| 削る機能 | リベンジモード、ミスした言葉の記録と優先出題、結果画面のふりかえり、難易度の選択 |
| 名前 | アプリ名とボス 20 体の名前を変える。フォルダ名は `typing-monster-sp` |

**仮に置いた値**（オーナーの確認はまだ）

- アプリ名: タイピングモンスター
- 評価の境目: ミス 0 回 = ★3 / 1〜2 回 = ★2 / 3〜4 回 = ★1 / 5 回以上 = ギリギリ勝利
- ミスは 1 バトルの通算で数え、5 回に達したらそのバトルの最後まで「いかり」のままにする

**理由と、選ばなかった案**

- **出題 API をやめる**: サーバーにお題を置いていたのは、正解を先に端末へ渡さないため。タイピングには隠す正解が無い。
- **標準のキーボードを使う**: ふだんの入力の練習になり、作る量も少ない。画面内に自前のフリックキーを並べる案は、濁点・小さい文字のキーまで自作になるので選ばなかった。
- **入力の試作を最初にやる**: 標準のキーボードは、確定する前の文字の扱いや予測変換が機種ごとに違い、「1 文字ごとに判定する」作りが成り立つかが分からない。成り立たないと設計が変わるので、設計書を書き直す前に、試作ページを Vercel に出して実機（iPhone・Android）で確かめる。確かめるのは判定の仕組みと、キーボードが出た状態での画面の収まり。試作の間、ほかの画面はクイズのまま残す。
- **ボス名は設計書の書き直しと同じ時に決める**: オーナーの希望。

GitHub のリポジトリと Vercel のプロジェクトはオーナーが作り、手順はエージェントが案内する。作業の順番は [`TODO.md`](../TODO.md#残っているタスク) にある。

## 2026-10-13 入力の試作ページ

TODO の 2-1。`/trial` に、スマホ標準のキーボードで 1 文字ごとの判定が成り立つかを確かめるページを作った（`src/modules/trial/`）。実機ではまだ確かめていない。

**作り**

- **判定は入力欄の中身の全体で行う**: 入力欄の中身が変わるたびに、お題と先頭から比べる（`judge.ts` の `judgeInput`）。1 文字打つごとに入力欄を空にする作りは、変換中の文字を何度も書き換えることになるので選ばなかった。入力欄を書き換えるのは、ミスのときと、言葉を打ち終えたときだけ。
- **途中の形**: 濁点・半濁点・小さい文字のキーを押すたびに切り替わる順番（は→ば→ぱ、つ→っ→づ など）を表で持ち、目当ての文字より前にある文字を途中の形とした。途中の形のまま次の文字を打ったらミス。
- **取り消し方を 3 つ切り替えられる**: A = 入力欄の中身を書きかえる / B = もう 1 つの入力欄へ移る / C = 何もしない（打った人が消す）。変換中の文字はキーボードの側も覚えているので、A では消えずに次の文字と一緒に戻ってくる機種がありうる。その場合の代わりの案が B。
- **予測変換**: 抑える指定（`autocomplete`・`autocorrect`・`autocapitalize`・`spellcheck`）の有り無しを切り替えられる。日本語のキーボードは指定があっても候補を出すことが多いので、候補を選ばれたら「お題と違う文字が入った」としてミスにする。
- **画面の収まり**: キーボードに隠れていない高さ（`visualViewport`）と、ボスとお題のかたまりの下端を測り、収まっているかを画面に出す。
- **記録**: キーボードから届いた通知（`input`・`compositionstart` など）を画面に出し、機種名と一緒にコピーできる。実機の結果は、これを貼ってもらえば分かる。

**確かめたこと**

- `pnpm lint`・`format:check`・`typecheck`・`test`（259 件。判定の単体テスト 14 件を足した）・`build` が通った。
- パソコンのブラウザ（幅 375px）で、正しい文字で進むこと、違う文字でミスが 1 回だけ増えて続きを打てること（A・B）、途中の形でミスが増えないことを確かめた。**変換中の文字の動きは、パソコンからは確かめられない**（実機の 2-5 で見る）。

**実機で見る点**（ページの一番下にも同じ一覧がある）

3. わざと違う文字を打つと、ミスが 1 回だけ増え、続けて正しい文字を打てるか（A・B・C のそれぞれ）
4. 予測変換の候補が出るか。候補を選んだらどうなるか

**決めた仕様**（設計書へ書き写すまでは、ここが正本）

| 項目 | 内容 |
| --- | --- |
| 遊ぶ人・端末 | 小学校高学年。スマホ（縦向き）。パソコンでも、日本語入力をオンにしたローマ字入力で遊べるようにする |
| 入力 | スマホ標準のキーボード（フリック入力）。ひらがなだけ。入力欄は見えるようにし、打った文字をそのまま出す |
| お題 | ひらがなの言葉をそのまま表示する。約 100 語、分類なし、難易度なし |
| 1 バトル | 5 問。通常 3 問（1 問 100 ダメージ）+ とどめ 2 問（残り HP の半分 → 残り全部） |
| ミスの判定 | 1 文字ごと。お題の次の文字と違う文字が入ったらミス 1 回とする。その文字は取り消さずに残し、打った人が消すキーで消してから打ち直す（2026-10-13 の実機確認で確定） |

| 失敗・ライフ | 無くす。問題を間違えるという考えが無いので、とどめの出し直しと予備の問題も無くす |
| いかり | ミスが 5 回以上で、ボスが「いかりの◯◯」になる |
| 評価 | ミスの回数で決める |
| 時間 | 制限時間も、速さの記録も入れない |
| お題の置き場所 | 画面側に持つ。出題 API はやめる |
| 削る機能 | リベンジモード、ミスした言葉の記録と優先出題、結果画面のふりかえり、難易度の選択 |

## 2026-10-13 入力の試作ページ

**作り**

- **判定は入力欄の中身の全体で行う**: 入力欄の中身が変わるたびに、お題と先頭から比べる（`judge.ts` の `judgeInput`）。1 文字打つごとに入力欄を空にする作りは、変換中の文字を何度も書き換えることになるので選ばなかった。入力欄を書き換えるのは、ミスのときと、言葉を打ち終えたときだけ。
- **途中の形**: 濁点・半濁点・小さい文字のキーを押すたびに切り替わる順番（は→ば→ぱ、つ→っ→づ など）を表で持ち、目当ての文字より前にある文字を途中の形とした。途中の形のまま次の文字を打ったらミス。
- **取り消し方を 3 つ切り替えられる**: A = 入力欄の中身を書きかえる / B = もう 1 つの入力欄へ移る / C = 何もしない（打った人が消す）。変換中の文字はキーボードの側も覚えているので、A では消えずに次の文字と一緒に戻ってくる機種がありうる。その場合の代わりの案が B。
- **予測変換**: 抑える指定（`autocomplete`・`autocorrect`・`autocapitalize`・`spellcheck`）の有り無しを切り替えられる。日本語のキーボードは指定があっても候補を出すことが多いので、候補を選ばれたら「お題と違う文字が入った」としてミスにする。
- **画面の収まり**: キーボードに隠れていない高さ（`visualViewport`）と、ボスとお題のかたまりの下端を測り、収まっているかを画面に出す。
- **記録**: キーボードから届いた通知（`input`・`compositionstart` など）を画面に出し、機種名と一緒にコピーできる。実機の結果は、これを貼ってもらえば分かる。

## 2026-10-13 試作ページをパソコンのローマ字入力に対応

オーナーの希望（パソコンでも遊べるとよい）で、試作ページの判定に足した。TODO の番号は無い。

- **やり方**: 入力欄の末尾にある英字（半角・全角、4 文字まで）を、「か→が」と同じ「打っている途中の形」として扱い、ミスにしない。ひらがなになった時点でお題と比べる。日本語入力はオンのまま使う。
- **選ばなかった案**: 日本語入力がオフでも遊べるように、キーを直接受け取ってローマ字→ひらがなの変換を自前で持つ案。変換表と打ち方の揺れ（si / shi、n / nn など）の対応が要り、スマホと別の仕組みを持つことになるので選ばなかった。
- **弱点**: ローマ字の打ち間違いはミスに数えない（ひらがなになってから違っていればミス）。日本語入力がオフのまま打つと進めないので、英字が 5 文字続いたらミスにし、「にほんご入力を オンにしてね」と出す。
- **確かめたこと**: `pnpm lint`・`format:check`・`typecheck`・`test`（265 件。判定のテスト 6 件を足した）が通った。ブラウザで、入力欄の中身を「s → さ → さk → さく → さくr → さくら」と変えてミスが増えずに次の言葉へ進むこと、「sakur」で案内が出ることを確かめた。**実際の日本語入力（変換中の文字の動き、スペースキーでの変換）では確かめていない。**

- **ミスの数え方（試作での作り）**: 入力欄の中身が変わったときにお題と違っていれば 1 回。消している途中（中身が短くなった）は数えない。細部は 3 の設計書で決める。

- iPhone での確認。言葉を打ち終えたときに入力欄を空にする動きが、iPhone の日本語キーボードで成り立つかは分かっていない。
